# Repository Guidelines

## Scope

This repository contains the GoldPrice Windows desktop client built with Tauri, plus the Go services it depends on. The app includes:

- a manager window
- a floating bubble window
- warehouse and PnL management
- chart rendering and K-line data
- tray, updater, ticket, and client-log flows

## Project Structure

- `src/`: frontend source
  - `manager-app.vue`: Vue shell for the manager window
  - `manager.js`: manager runtime, SSE flow, view switching, settings, preview, updater, tickets
  - `bubble-app.js`: bubble entry
  - `bubble.js`: bubble rendering, snapshot consumption, resize/show logic
  - `runtime.js`: Tauri API access, logging helpers, runtime utilities
  - `datasource.js`: field map, display names, currencies, heartbeat, update metadata
  - `chart.js`, `kline_cache.js`, `kline_data.js`: chart and K-line logic
  - `warehouse.js`: warehouse, trade history, cost, PnL logic
  - `config.example.js`: sanitized local config template
- `src-tauri/`: Rust backend and app packaging
  - `src/main.rs`: window lifecycle, tray, updater, logging, Tauri commands
  - `tauri.conf.json`: window and updater config
- `remote-servers/`
  - `app-control`: updater metadata, legacy version/message/ping APIs, light control APIs
  - `market-stream`: `/fields`, `/stream`, upstream price aggregation, K-line generation
  - `ticket-center`: ticket submission and management
- `docs/`: release and updater docs
- `scripts/`: helper scripts such as version sync

## Build And Run

- `npm install`
- `npm run frontend:dev`
- `npm run dev`
- `npm run frontend:build`
- `npm run build`
- `npm run build:windows:x64`
- `npm run build:release`
- `npm run build:release:windows:x64`
- `npm run setver -- <version>`
- `npm run updater:keygen`

For backend or service work:

- `cd src-tauri && cargo test`
- `cd remote-servers/<service> && go test ./...`
- `cd remote-servers/<service> && go run .`

## Local Config

Before local development:

```powershell
Copy-Item src\config.example.js src\config.js
```

`src/config.js` must stay Git-ignored and keep the same ESM shape as the example.

Important expectations:

- `SERVER_URL` drives `${SERVER_URL}/fields` and `${SERVER_URL}/stream`
- `COS_CDN` is used for K-line JSON
- `TICKET_SERVER_URL` is used for ticket APIs
- Tauri updater metadata is served from `https://api.zargo.top/updates/stable/latest.json`
- do not commit real service URLs, secrets, or signing material

## Updater And Release Flow

The current client uses the Tauri official updater only.

- Stable updater endpoint: `https://api.zargo.top/updates/stable/latest.json`
- Update notes come from `latest.json` field `notes`
- Update notes are shown only in the update modal
- Do not reintroduce independent announcement APIs or UI
- Removed announcement endpoints should stay removed: `/announcements/latest`, `/releases/latest`
- Legacy compatibility endpoints may remain for old clients: `/version`, `/message`, `/ping`, `/api/v2/update`, `/api/v2/message`, `/api/v2/heartbeat`
- Earlier clients read the legacy message endpoint from `/message`; `/api/v2/message` is only the v2 compatibility path

COS release artifact naming is fixed:

- Installer: `GoldPrice_{version}_x64-setup.exe`
- Updater package: `GoldPrice_{version}_x64-setup.nsis.zip`
- Updater signature: `GoldPrice_{version}_x64-setup.nsis.zip.sig`

The updater JSON must use the updater zip URL:

```text
https://apk-1304316935.cos.ap-guangzhou.myqcloud.com/GoldPrice_{version}_x64-setup.nsis.zip
```

The `platforms.windows-x86_64.signature` value must be the full text content of the local `.zip.sig` file generated by Tauri, not a URL.

Release build checklist:

- `npm run setver -- <version>`
- `$env:TAURI_PRIVATE_KEY="$env:USERPROFILE\.tauri\goldprice-updater.key"`
- `$env:TAURI_KEY_PASSWORD=""`
- `npm run build:release:windows:x64`
- Upload exe, updater zip, and `.zip.sig` to COS
- Update server `latest.json` with `version`, `notes`, `pub_date`, `url`, and signature text

## Frontend Boundaries

- Keep the frontend on native Vite ES modules
- Prefer explicit imports/exports over `window.*` globals
- Keep Tauri access centralized through `runtime.js`
- Do not restore `src/echarts.min.js`; use the npm `echarts` package
- Prefer DOM event binding over new inline `onclick` / `onchange`

Sensitive chains to avoid breaking:

- price startup: `/fields` -> `/stream` -> manager snapshot -> bubble render
- bubble config: manager localStorage save -> `config-update` / `bubble-refresh-now` -> bubble reload
- warehouse PnL: manager prices -> `warehouseModule.updatePrices(...)` -> summary/detail render
- chart fetch: `chartModule.configure({ httpFetch })` must keep using Tauri HTTP
- updater: startup check should show the update modal when a new version exists; if dismissed, keep green update hints on the settings button and app settings nav item
- update modal: avoid nested scrolling; the modal itself should not scroll, only the fixed update-notes block should scroll

## Logging

Use the Tauri-backed client log flow as the primary diagnostic path.

- Prefer `append_client_log` / `appendClientLog`
- Keep structured module/event naming
- Avoid noisy per-frame, per-render, or per-tick logs
- Do not use raw `console.log` / `console.error` as the main observability path

Client logs are stored under `%APPDATA%\com.lucas.goldprice\logs\app.log`.

## Style

- Use 2-space indentation for JS, Vue, HTML, and CSS
- Keep lowercase feature-oriented file names
- Preserve existing TDesign/Vue patterns
- Add comments only when clarifying non-obvious logic
- Format Rust with `cargo fmt`
- Format Go with `gofmt`

## Testing

There is no dedicated frontend test suite yet. At minimum:

- run `npm run frontend:build`

When desktop/runtime code changes:

- run `npm run dev`

Smoke test touched flows:

- manager startup, EULA, theme, navigation, window controls
- `/fields`, SSE connect, first snapshot, reconnect, failure state
- bubble render, resize, show/hide, config changes, PnL lines
- warehouse list/detail, buy/sell, adjustment, realtime PnL
- chart ranges, refresh, currency switch, theme
- updater modal on startup when a new version exists, dismiss behavior, green update hints, Tauri updater install path
- ticket submission with client logs

## Commits And PRs

- Keep commit subjects concise and imperative
- Conventional Commit prefixes are welcome but optional
- Keep each commit focused
- PRs should describe behavior changes, checks performed, and include screenshots for visible UI work

## Security And Generated Files

Do not commit:

- `src/config.js`
- local service URLs, secrets, updater keys, private certs
- bundles, installers, logs
- `node_modules/`, `dist/`, `src-tauri/target/`
- temporary target directories or downloaded runtime artifacts

Keep examples in `src/config.example.js`, `docs/`, and `remote-servers/` sanitized.
